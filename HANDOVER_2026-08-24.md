## 1. The one substantive bug, and what it cost

**Eq (6) of the manuscript is wrong.** It states the scale augmentation rescales
the regression target as `BF' = BF · s³`. It should be `BF' = BF · s`.

BF is already a cube root (`BF = M^⅓ / L`), so simulating a shrink by `s` gives
`(s³M)^⅓ / L = s · BF`. Cubing applies the exponent twice.

This was **not a typo in the write-up** — `02-train.py` did exactly what Eq (6)
says, so the submitted model was trained under the wrong exponent. Fixed in
commit `783179b`; the line now reads

```python
target = float(row["BF_cbrMG_MM"]) * scale
```

**It cost very little.** A corrected retrain moves test MAE from 0.0824 to
0.0807 with almost totally overlapping bootstrap CIs. The augmentation was still
monotone in scale, just with the wrong exponent, so the model largely learned
around it. **The paper's conclusions are unaffected.**

`README.md:38` still repeats the same error ("rescales the target by the cube of
the scale factor") and needs the same correction.

`1d23c69` "fix wrong dpi in beetles!" — DPI feeds SCALE feeds BF, so the *labels*

estimates the validation-set variance:

| implied val SD | runs | best MAE |
|---|---|---|
| 0.05035 | `2026-01-30_15-00-26`, `2026-01-30_16-22-35` | 0.01458, 0.01465 |

The often-quoted "0.01458 best ever" is from the *old* label set, which has ~10%

originally used to estimate it turned out to straddle two validation sets. Nobody
should treat a ~0.0005 difference as real until someone runs 3 seeds per arm
(~9 h at 250 epochs, which is past where the optimum lands).

## 4. Two findings worth putting in the paper

### 4a. Specimen-level aggregation is an 11% free win

There are ~3 images per specimen. Averaging a specimen's predictions takes test
MAE from **0.0807 to 0.0719** with no retraining. The analysis currently reports
the single-random-image estimator, which understates what the pipeline delivers
if the deployment unit is a specimen rather than an image.

### 4b. Point-estimate mass is biased ~4.5% low

Since `M = (BF·L)³` and `E[X³] ≠ E[X]³`:

```
E[M] ≈ (L·μ)³ (1 + 3s²)     with s = relative error ≈ 0.123  →  3s² ≈ 4.5%
```

For a single specimen this is noise. **For summed community biomass it does not
average out — it accumulates as a one-sided underestimate.** Either correct it
analytically or state it. Getting a predictive distribution rather than a point
estimate would let you do the former; a Gaussian-NLL head (predict μ and log σ)
or the spread of a seed ensemble would both suffice, and the ~3 replicate images
per specimen give a rare opportunity to *validate* the calibration.

## 5. Where the remaining error actually lives

Decomposed on the validation split (3,142 specimens, 3.02 images each):

| predictor | MAE | R² |
|---|---|---|
| predict global mean (trivial) | 0.04202 | 0.000 |
| **the model** | **0.01538** | 0.843 |
| oracle: predict each specimen's *mean* BF | 0.01008 | 0.919 |

The model closes **83%** of the distance from trivial to the specimen-level
oracle. Of the remaining error, a large part is not about the animals at all:

| quantity | within-specimen CV |
|---|---|
| `DRYMASS_MG` | **0.0%** (measured once per specimen) |
| `ROI_SIZE_MM` | 6.1% |
| `SCALE` | 6.1% |
| `BF_cbrMG_MM` | 6.1% |

`M` is constant per specimen, so **every** within-specimen label difference comes
from the length/scale measurement. The same physical insect carries labels
differing by ~6% depending on which image it is.

**No leakage**: 0 of 3,142 specimens span more than one split — the split is
properly grouped by specimen, so the validation number is honest.

### Other manuscript issues

- **"approximately 8,400 images of 2,100 individual specimens"** (line 187)
  contradicts the paper's own Figure 3a table, which sums to **7,444 images /
  2,123 specimens** — and the table is the one that matches the data exactly.
  The README repeats the 8,400 figure.
- **Abstract "R² > 0.95"** overstates: EntoScan 0.95, Biodiscover 0.89. Neither
  exceeds 0.95, and the claim generalises from the better dataset.
- **The Type III ANOVA + emmeans post-hoc described at lines 304–309 is not in
  the repository.** Figure 3b's `***`/`ns` annotations depend on it; no `Anova()`,
  `aov()`, `emmeans` or log-transform exists anywhere in the repo. **This is a
  reproducibility gap someone needs to close.**
- **The `conf > 0.90` detection filter is undocumented.** Both case studies apply
  it; for spiders it discards 3,296 → 2,421 detections (26%).
- **The spider case study contains two species, not one.** PD (*P. degeeri*,
  1,913) and BG (1,383) across the four named sites. "1,913 individuals were
  imaged" is the PD count, not what was imaged (3,296). Fig 3c's caption promises
  "species-specific patterns" while showing one species — a leftover from a
  two-species figure. The analysis code still generates both panels.

## 8. Suggested next steps, in order

1. **Three seeds per arm** at ~250 epochs, to finally measure run-to-run variance.
   Nothing below ~0.001 should be believed until this exists.
2. **Add the specimen-aggregated row** (§4a) to the results table — 11%, free.
3. **Close the ANOVA reproducibility gap** (§6) — the code for Figure 3b's
   significance annotations is not in the repo.
4. **Correct Eq (6) and `README.md:38`**, and state that the reported model was
   trained under the erroneous exponent with a note that a corrected retrain
   changes test MAE by ~2% with overlapping CIs.
5. Consider a **Gaussian-NLL head or seed ensemble** for §4b, and validate its
   calibration against the replicate-image spread.
6. **An elastic-transform ablation.** Measured displacement is only **0.67 px
   mean / 3.6 px worst-case** on a 224 px image (torchvision normalises by image
   size, so `α=50` is much gentler than it sounds). It is almost certainly too
   weak to regularise *or* to corrupt the shape signal. It arrived as one of
   three simultaneous changes in `fa75ae5` and its individual effect has never
   been isolated.

## 9. Things to be careful about

- **Never compare across the validation-set eras** (§2). This invalidated several
  hours of my own analysis before I caught it.
- **`Rplots.pdf` vs `analysis.pdf`** (§7).
- The drosophila and spider case studies have **no ground-truth mass** — they are
  applications, not validations. Swapping the model changed their population
  biomass estimates by +6% and +19% respectively, with nothing to check against.
  The current PDFs use the new model; treat them as provisional until someone
  decides whether to adopt it, given that it is *not* demonstrably better on test.
- `01_biomass_model/best_model.pt` (repo root) is still the **February** model.
  Only `01_runs/.../NoSmooth_2026-08-23_19-20-21/best_model.pt` is current.
